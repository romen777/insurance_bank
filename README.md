# insurance_bank — 보험심사 근거자료 은행

「요양급여의 적용기준 및 방법에 관한 세부사항과 심사지침」(심평원 발간)을
조각으로 만들어 두는 곳. **메디클라우드 QA 자동답변이 인용하는 행위·치료재료 근거원**이다.

```
insurance_bank/
├── source/                  원본 PDF — 커밋한다. 추출이 의심스러우면 여기로 되짚는다
├── data/
│   ├── chunks.jsonl         ★ RAG 자산. 한 줄 = 한 조각
│   └── manifest.json        판본·쪽수·조각수·부문 분포
├── scripts/
│   ├── build_corpus.py      PDF → chunks.jsonl
│   ├── diff_editions.py     판 대조 — 신설·개정·폐기
│   └── sync_supabase.py     chunks.jsonl → 비공개 Supabase
└── .env                     Supabase 자격증명 (커밋하지 않는다)
```

## 왜 git 인가 — 해마다 판이 바뀌기 때문

이 자료는 매년 새 판이 나오고, **바뀐 기준을 폐기하고 새것으로 인용**해야 한다.
DB 한 곳에 두고 `expire_ymd` 를 사람이 찍는 방식은 필터를 한 군데만 빠뜨려도
폐기된 기준이 답변에 인용된다.

git 에서는 새 판을 커밋하면 사라진 조각이 **파일에서 없어진다**. 인용 자체가 불가능해진다.
그리고 무엇이 신설·개정·폐기됐는지 `git diff` 가 그대로 보여 준다.

### 그래서 id 가 위치에 기대면 안 된다

부문별 순번(`Ⅰ-0001`)으로 매기면 앞에 조각 하나만 늘어도 뒤가 전부 밀려
diff 가 「2,500줄 전부 변경」이 된다. 그래서 id 는 **내용**으로 짠다 —
`항목코드 + 제목 + 장` 의 해시. 그것만으로 겹치는 조각은 본문 앞머리를 보탠다.

```
Ⅰ-437dd3f2        판이 바뀌어도 같은 조각이면 같은 id
Ⅰ-437dd3f2#2      본문이 길어 나뉜 조각
```

## ⚠ 이 저장소는 공개(public)이다

심평원이 공개 배포하는 자료만 둔다. 한 번 올라가면 지워도 이력에 남는다.

| 넣지 않는 것 | 어디에 두나 |
|---|---|
| 명세서·환자 정보 | 어디에도 두지 않는다 |
| 골키퍼 룰 내용·판정 알고리즘 | 비공개 |
| 이지스 운영DB 표명·소스 | 비공개 |
| 원장님 미공개 저작물(당뇨병 길라잡이 등) | 비공개 Supabase |
| API 키·자격증명 | `.env` (gitignore) |

올리기 전에 한 번 돌리십시오.

```bash
python scripts/precommit_check.py
```

## 쓰는 법

```bash
# 1. PDF → 조각
python scripts/build_corpus.py

# 2. 지난 판과 대조 (새 판을 넣기 전에 무엇이 바뀌는지 먼저 본다)
python scripts/diff_editions.py --against v2026-07

# 3. Supabase 로 동기화 — git 에 없는 조각은 자동으로 폐기된다
python scripts/sync_supabase.py --edition 2026-07

# 4. 판을 태그로 못 박는다
git tag ref-2026-07 && git push --tags
```

## 새 판이 나오면

1. `source/` 의 옛 PDF 는 **지우지 않고** 새 PDF 를 나란히 둔다
2. `build_corpus.py` 재실행 → `chunks.jsonl` 갱신
3. `git diff data/chunks.jsonl` 로 신설·개정·폐기를 눈으로 확인
4. `sync_supabase.py` 실행 — DB 에서 사라진 조각이 `use_yn='N'` 이 된다
5. 커밋 + 태그

옛 판은 태그로 남는다. 「2026년 진료분은 그때 기준으로」를 되짚을 자리가 있어야 한다.
